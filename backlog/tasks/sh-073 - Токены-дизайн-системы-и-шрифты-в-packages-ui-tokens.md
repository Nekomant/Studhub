## Description

## Что нужно сделать
1. Создать `packages/ui-tokens`: CSS-переменные всех токенов `design-system.md` (цвета обеих тем, отступы, радиусы, высоты, тени, стили текста).
2. Сделать переключение темы: без класса на `<html>` всегда светлая тема (системную настройку `prefers-color-scheme` пакет не учитывает), класс `dark` включает тёмную, класс `light` светлую. Режим «Как в системе» ставит класс скриптом в SH-022.
3. Описать тему Tailwind CSS v4 на этих переменных и задать переменные shadcn/ui по таблице §8.
4. Положить в пакет шрифты Nunito 800 и Manrope 300, 400, 600 в `woff2` с подмножествами latin и cyrillic, подключить через `@font-face`.
5. Сделать страницу-образец пакета для визуальной проверки владельцем.
6. Написать тесты по критериям.

## Зачем
Внешний вид согласован (`docs/design-system.md`, решения ДС-1…ДС-8), но в коде его ещё нет. Каркас SPA (SH-008) и лендинг (SH-015) должны с первого дня брать цвета, шрифты и размеры из одного пакета, иначе значения разойдутся по файлам, а тёмную тему придётся доделывать по всем экранам. Пакет общий для `apps/web` и `apps/landing` (ТД §2.4).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Оценка: 6 ч

Решение: AC-2 проверяем браузерным тестом через библиотеку playwright (Chromium) из обычного Vitest-теста, а не Vitest browser mode. Почему: нужен один тест и одна зависимость, без отдельного проекта Vitest с провайдером (@vitest/browser-playwright) и без второго окружения; тест может читать CSS с диска и открывать страницу в Chromium. Playwright и так выбран для E2E (ТД §3), так что Chromium потом нужен будет в любом случае. Влияние: dev-зависимость playwright в packages/ui-tokens, в CI шаг playwright install chromium.

Решение владельца (2026-11-12): по умолчанию в пакете светлая тема. Без класса на <html> всегда светлые цвета, prefers-color-scheme пакет не учитывает; тёмная только классом dark, класс light тоже даёт светлую. Режим «Как в системе» из Э-17 остаётся по умолчанию и ставит класс скриптом (SH-022); ДС-6 и screens.md не меняем. Текст AC-2, описание и план тестов обновлены. Браузерный тест проверяет: без класса при системной тёмной светлые цвета; dark тёмные; light при системной тёмной светлые.

Решение: тема в CSS задана через color-scheme и light-dark() (одно объявление на токен, без дублирования значений). :root { color-scheme: light }, .dark { color-scheme: dark }, .light { color-scheme: light }.

Решение: в design-system.md §6 'space-1 … space-8' перечислено 6 значений (4, 8, 12, 16, 24, 32). Читаем как шаги Tailwind: space-1, 2, 3, 4, 6, 8 (1 шаг = 4 px). Токены space-1/2/3/4/6/8, в Tailwind --spacing: 4px, утилиты p-6 = 24 px, p-8 = 32 px.

Факт: 5 ч

Решение: Tailwind в задачу не ставили (SH-008). Тест AC-3 проверяет текст theme.css, а не собранные утилиты: ключи @theme и @utility сверены с design-system.md. Ключи радиусов rounded-sm/md/lg (а не rounded-s), чтобы не пересечься со встроенным rounded-s Tailwind и не сломать компоненты shadcn. radius-pill, shadow-*, font-heading в теме продублированы значением (ссылка на самого себя ломает переменную), тест сверяет с tokens.css.

Факт по документу: в подмножествах latin и cyrillic нет знака рубля U+20BD, он выводится системным шрифтом. У Nunito нет tnum (у Manrope есть), для заголовков это не важно; design-system.md ДС-2 исправлен. Тест tnum проверяет только Manrope.

Факт по тестам: после красного коммита правились только вспомогательные части тестов (число токенов 26 вместо ошибочных 30, нормализация записи 0.40 и 32px / 36px после форматирования Biome, tnum только для Manrope). Критерии и проверки по ним не менялись.

Замечание: тест SH-005 AC-1 (db:migrate, таймаут 5 с) иногда падает при полном прогоне vitest и без пакета ui-tokens; не связано с SH-073.

Проверка тестов (sh-verifier): AC-1…AC-5 подтверждены, AC-6 ручная. Нарушений нет. Замечание: проверка tnum в fonts.test.ts после красного коммита сужена до Manrope, ДС-2 поправлен так же (у Nunito в файлах @fontsource нет tnum); критерий AC-4 tnum не требует, показываем владельцу в PR. AC-2 изменён по ответу владельца до красного коммита.

Решение по замечанию ревью: light-dark() заменён обычными объявлениями (iOS 17.4 и старше его не знают, все цветовые переменные были бы невалидны). Светлые значения в блоке ':root, .light', тёмные в '.dark', color-scheme оставлен. Производные переменные (shadcn-маппинг §8, составные тени) повторены в обоих блоках, иначе вложенный блок с другим классом унаследует значение родителя. Пункт плана 4 читать так. Тесты AC-1/AC-2/AC-5: изменён только разбор в tests/support/css.ts (themePair), проверки критериев те же. theme.css: сохранены --color-white и --color-black для bg-black/50 и text-white из shadcn (добавлена проверка в AC-3). README: шаг playwright install chromium.

Повторная проверка тестов (sh-verifier) после правок ревью: AC-1…AC-5 подтверждены, AC-6 ручная. Сужение проверки tnum до Manrope оставлено: в файлах Nunito 800 от @fontsource нет tnum, Nunito набирает только заголовки, а цифры в интерфейсе набираются Manrope (ДС-2 поправлен). Критерий AC-4 tnum не требует; строка плана тестов читается так: табличные цифры проверяются у Manrope. Решение показано владельцу в PR.

Владелец принял: Nunito без табличных цифр, числа набираем Manrope (ответ «А» на вопрос в PR #28).
