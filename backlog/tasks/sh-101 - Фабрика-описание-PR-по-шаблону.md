## Что нужно сделать
1. Написать тесты по критериям до реализации в `tools/tests/factory.test.ts` с фикстурами SH-097. Подставной `gh` пишет содержимое `--body-file` в журнал.
2. Тело PR фабрика строит только перед `gh pr create` (SH-097, шаг 3.5) и заменяет им тело из двух строк: если `pr_url` есть или `gh pr list` нашёл PR, `git fetch`, `git diff`, чтение шаблона и запись `pr-body.md` не выполняются, а тело PR после `fix` (SH-096) не меняется. Фабрика читает `.github/pull_request_template.md` из worktree задачи и заменяет содержимое под каждым заголовком `## ` своим текстом: заготовки шаблона (одиночная строка `-`, строки ``- `pnpm verify`:`` и `- Ручные проверки по плану тестов задачи:`, HTML-комментарии) в теле не остаются. Комментарий перед `## Задача` удаляется. Раздел «Чек-лист ревью» остаётся как в шаблоне, без отметок: его проверяет владелец. Первая строка тела — «Собрано фабрикой». Разделы:
   - «Задача»: `SH-NNN: <название>, файл задачи в backlog/tasks/`;
   - «Что сделано»: итоговое резюме задачи (`--final-summary`); если его нет — «Итоговое резюме не записано»;
   - «Как проверено» — строки по порядку:
     - `- pnpm verify: <verify_summary>`;
     - `- Проверка тестов: <текст после двоеточия из последней строки заметок, которая начинается с «Проверка тестов:»>`; если такой строки нет или после двоеточия пусто — `- Проверка тестов: нет критериев с автоматическим уровнем`;
     - `- Кругов исправлений: <rounds_total>`;
     - `- code-review: ЗАМЕЧАНИЙ: <review_count>`;
     - `- Ручные проверки:` и под ней `  - [x] AC-n <текст>` по каждому критерию «Ручная» (все они отмечены: шаг 3.1 не пропустит неотмеченный), либо `- Ручные проверки: нет`;
     - `- Проверить владельцу:` и под ней `  - [ ] AC-n <текст>` по каждому критерию «Ревью», либо `- Проверить владельцу: нет`;
   - уровень критерия определяется по строкам плана тестов через `normalizeLevel` из `scripts/lib/backlog-task.mjs`: критерий идёт в «Ручные проверки», если у него есть строка «Ручная», и в «Проверить владельцу», если все его строки «Ревью»; критерий без строки плана в эти списки не попадает;
   - критерии «Скрипт» в теле не выводятся: их доказательство воркер пишет в заметки задачи;
   - заметки и итоговое резюме фабрика читает теми же полями, что `scripts/task.mjs` (`implementationNotes`, `finalSummary`);
   - «Изменения документов»: после `git fetch origin main` — по строке `- <путь>` на каждый файл из `git diff --name-only origin/main...HEAD` в `docs/`, `.claude/`, корневых `CLAUDE.md` и `README.md` (не `apps/web/README.md`), либо `- нет`.
3. Сбой `git fetch`, `git diff`, чтения шаблона PR или записи `pr-body.md` ставит этап «ошибка PR» с `reason` вида `<команда>: <первая непустая строка stderr, иначе stdout>`, для шаблона — `чтение .github/pull_request_template.md: <ошибка>`, и шлёт уведомление, как в SH-097.
4. Обновить документы:
   - `docs/process.md` §7 (шаг 8): что фабрика пишет в описание PR и откуда берёт данные;
   - `docs/process.md` §10: в PR фабрики чек-лист ревью проверяет владелец, пункт «/code-review пройден» он сверяет со строкой `ЗАМЕЧАНИЙ: 0`.

## Зачем
Владелец решает о слиянии по описанию PR. Сессия на Opus сейчас пишет его по шаблону вручную. Все данные для описания уже есть в задаче, заметках, состоянии фабрики и диффе, поэтому фабрика собирает его без модели: итоги проверок, сомнительные места и критерии, которые нужно проверить владельцу.

## Контекст
- Шаблон PR: `.github/pull_request_template.md`.
- Процесс: `docs/process.md` §7 (шаг 8), §10.
- Фабрика: SH-097 (шаги PR, `pr-body.md`, «ошибка PR»), SH-095 (`verify_summary`, `rounds_total`), SH-099 (строка «Проверка тестов:»), SH-100 (`review_count`).
- Разбор плана тестов: `scripts/lib/backlog-task.mjs` (`parseTestPlan`); заметки и резюме: `scripts/task.mjs` (`implementationNotes`, `finalSummary`).
- UC и экраны: нет, задача про процесс разработки.

## Не входит
- Шаги PR, метка, `pr_url`: SH-097.
- Обновление тела PR после `fix`: тело строится только перед `gh pr create`.
- Правка самого шаблона PR.

## Контракт
API и БД не меняются. Новое: сборка тела PR в `scripts/factory.mjs`.
