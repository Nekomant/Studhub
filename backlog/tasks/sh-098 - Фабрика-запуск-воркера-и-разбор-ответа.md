6. Разбор ответа без модели — функция `parseWorkerReply({ stdout, code, error, taskId, sessionId })` (`error` — ошибка запуска процесса) возвращает `{ stage, reason, cost, denials, sessionReady }`; `sessionReady` true, если `session_id` ответа равен `sessionId`. `applyWorkerReply(id, reply)` пишет результат в запись: ставит этап и `reason`, прибавляет `cost` к `cost_usd`, заменяет `denials`, ставит `session_ready` true при `sessionReady` true (обратно в false не сбрасывает). pid и `pid_started_at` очищает фоновый процесс при своём выходе, а не `applyWorkerReply`; `saveReply(id, role, stdout)` пишет ответ в папку задачи. Порядок разбора: сначала проверяются причины ошибки по списку ниже; `result` разбирается, только если ни одна не сработала. Тогда первая непустая строка `result`: равна `ГОТОВО SH-NNN` с ID задачи — «готово»; начинается с `СТОП SH-NNN:` с ID задачи — «стоп»; равна `ЗАМЕЧАНИЯ SH-NNN` с ID задачи — тоже «стоп»: это вопрос владельцу о попутных замечаниях (`docs/process.md` §7.1, «Попутные замечания»), владелец отвечает на него так же, как на `СТОП`; совпадает с `^(ГОТОВО|СТОП|ЗАМЕЧАНИЯ) SH-\d+` с другим номером (например, `ГОТОВО SH-0980`) — «ошибка», `чужой ID`; всё остальное — «ошибка», `неизвестный ответ`. Без валидного JSON `cost` 0, `denials` пустой массив, `sessionReady` false. `reason`: для «стоп» — первая строка ответа (`СТОП SH-NNN: …` или `ЗАМЕЧАНИЯ SH-NNN`), для «готово» — пусто, для «ошибка» — первая подошедшая причина в таком порядке: `claude не запустился: <ошибка>`, `невалидный JSON`, `ошибка claude: <subtype>` (если `subtype` начинается с `error`, например `error_max_budget_usd`), `is_error`, `код <N>`, `нет result`, затем по `result`: `чужой ID`, `неизвестный ответ`. Стоимость и отказы берутся из валидного JSON при любой причине. Первая строка совпадает с `ГОТОВО SH-NNN` целиком или начинается с `СТОП SH-NNN:`. Каждый ответ, в том числе невалидный stdout как есть, пишется в папку задачи файлом `NNN-worker.json`, где NNN — максимальный номер среди всех файлов ответов задачи плюс один (`saveReply` с ролью `worker`; SH-099 и SH-100 используют роли `verifier` и `review`). `denials` хранится массивом объектов `permission_denials` как есть, без поля — пустой массив. JSON `claude` — `result`, `session_id`, `total_cost_usd`, `permission_denials`. Первая непустая строка `result` после обрезки пробелов: `ГОТОВО SH-NNN` с ID этой задачи даёт этап «готово», `СТОП SH-NNN: …` — этап «стоп». Другой текст, ID другой задачи, ненулевой код, невалидный JSON, `is_error: true` или нет поля `result` (например, превышен бюджет) дают этап «ошибка» с причиной в `reason`. Если JSON валиден, `total_cost_usd` прибавляется к `cost_usd` и отказы пишутся в `denials` при любом коде; `session_ready` становится `true`, если `session_id` ответа совпал с записанным.
7. Обновить документы (команды с флагами только в `README.md`, правило SH-081):
