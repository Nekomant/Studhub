## Что нужно сделать
1. Написать `docker-compose.yml` с `postgres:18` и Garage (локальный S3, замена MinIO, ADR-0008); бакет файлов Garage создаёт сам при старте (`--default-bucket`); данные хранить в именованных томах.
2. В `apps/api/src/platform/config` описать схему переменных окружения на zod; при ошибке приложение печатает список проблем и завершается.
3. Покрыть схему конфигурации юнит-тестами.
4. Создать `.env.example` со всеми переменными и комментариями.
5. Настроить отдельную тестовую БД и скрипты `pnpm db:up`, `pnpm db:down`, `pnpm db:reset-test`.
6. Описать в README, как поднять окружение.

## Зачем
Разработка и API-тесты должны идти на тех же Postgres 18 и S3 API, что в prod, без ручной настройки.

Изменение по ходу задачи (согласовано владельцем 2026-11-11): образы MinIO недоступны, поэтому локальный S3 — Garage; версионирование бакета отменено. Правки в ТД, UC-42, ADR-0007, ADR-0008.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Оценка: 4 ч

Решения и факты по ходу работы:
- Официальные образы MinIO на Docker Hub не публикуются с осени 2025 (сообщения о прекращении выпуска community-образов). Образ minio/mc тоже. Поэтому MinIO-сервис в compose пока не добавлен. Ждёт владельца: выбор S3-сервера для локального окружения (см. ниже).
- Postgres 18 поднят (postgres:18, именованный том postgres-data, данные переживают restart). Проверено: БД 18.6, строка сохранилась после docker compose restart.
- db:reset-test пересоздаёт studentshub_test, dev-БД не затронута (проверено; отказ при совпадении имён и при имени без _test).
- На порту 5432 у владельца уже работает контейнер start-db (postgres:16-alpine). Проверки шли на 5433 через POSTGRES_PORT. Порт по умолчанию не менял.
- .env.example написан, но коммит заблокирован хуком block-bad-commands (сработал на путь .env.example). Ждёт владельца: закоммитить файл вручную или разрешить.
