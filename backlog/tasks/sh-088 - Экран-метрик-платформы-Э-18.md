## Что нужно сделать
1. Написать API- и E2E-тесты по критериям до реализации.
2. Сделать `GET /api/admin/v1/metrics/{report}` для отчётов Э-18: «Открытые уроки по неделям», «Уроки с итогом», «Исправления автоматических статусов», «Активные преподаватели», «Когорты удержания», «Воронка онбординга», «Использование функций», «Преподаватели». Данные берутся из представлений `analytics` (SH-065) и открытых данных преподавателей; данных учеников в ответах нет.
3. Сделать экран Э-18 `admin.studshub.ru/metrics/{report}` в `apps/admin` (SH-076): переключатель отчётов и таблица отчёта. На ширине меньше 768 px таблицы прокручиваются по горизонтали внутри блока.
4. Показать экран только сотруднику с сессией `sh_admin_session`; без сессии открывается вход (SH-085) либо 404.
5. Каждый запрос отчёта пишется в `admin_audit` (SH-086).
6. Отчёты из `scripts/metrics.sql` (SH-065) и экран должны давать одни и те же числа: сверить на тестовых данных.
7. Обновить `docs/screens.md` Э-18, ТД §11 и UC-P1: экран есть, метрики из SQL больше не единственный способ.

## Зачем
До стадии 3 метрики платформы смотрят SQL-запросами по SSH (SH-065). Экран в админке заменяет их для сотрудников, у которых нет доступа к серверу, и делает метрики воспроизводимыми и аудируемыми (UC-P1, ADR-0009, п. 7).

## Контекст
- Сценарии: UC-P1.
- Экраны: Э-18.
- Правила: ТД §11 (метрики и представления `analytics`), §6 (админка платформы), ADR-0009, п. 7.
- Зависит от SH-065 (события и представления), SH-076 (приложение), SH-085 (сессия админки), SH-086 (аудит).

## Не входит
- Новые метрики и новые представления: только те, что описаны в ТД §11 и сделаны в SH-065.
- Экспорт отчётов, графики, фильтры по периодам.
- Данные учеников и кабинетов: только агрегаты и список преподавателей.

## Контракт
- `GET /api/admin/v1/metrics/{report}` → `{ report, columns, rows, generatedAt }`; `report` из закрытого списка отчётов.
- Ошибки: 404 для неизвестного отчёта и для не-сотрудника.

## План тестов
| AC | Уровень | Тест |
|---|---|---|
| 1 | API | сотрудник получает каждый из восьми отчётов; неизвестный отчёт → 404 |
| 2 | API | в ответах нет данных учеников; список преподавателей содержит только разрешённые поля |
| 3 | API | без сессии админки и с `sh_session` → 404 |
| 4 | API | каждый запрос отчёта оставляет запись `ok` в `admin_audit` |
| 5 | API | числа отчётов совпадают с запросами `scripts/metrics.sql` на тестовых данных |
| 6 | E2E | сотрудник открывает Э-18, переключает отчёты, видит таблицу; на 375 px таблица прокручивается внутри блока |
| 7 | Ревью | `screens.md` Э-18, ТД §11 и UC-P1 обновлены |
