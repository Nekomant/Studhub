## Что нужно сделать
1. Написать тесты по критериям до реализации в `tools/tests/factory.test.ts` с фикстурами SH-093–SH-095. Подставной `gh` пишет аргументы и содержимое `--body-file` в журнал. Этапы проверяются по журналу смен этапов `log.txt` (SH-093): так тест SH-095 про «готово к PR» остаётся верным, хотя после этой задачи процесс идёт дальше.
2. Этап «готово к PR» перенести в список этапов, где работает процесс (`scripts/lib/factory-state.mjs`): с него фоновый процесс сразу выполняет шаги PR, уведомления на нём нет. Если процесс умер на «готово к PR», сводка, `run`, `answer` и `continue` ставят «ошибка PR» с `reason` «процесс завершился без ответа» (вместо «ошибка» из SH-094).
3. Шаги PR (все команды с `cwd` — worktree задачи):
   1. проверка отметок. Критерии с уровнем «Ревью» в плане тестов не проверяются: владелец проверяет их по PR и отмечает командой `backlog task edit SH-NNN --check-ac N` в worktree задачи до `pnpm factory done`; `done` (SH-096) коммитит файл задачи целиком вместе с этими отметками. Критерии «Юнит», «API», «E2E» и «Скрипт» отмечает воркер с доказательством. Если неотмечен любой критерий, кроме «Ревью», этап «нужен владелец», `reason` — `не отмечены: AC-3, AC-5`, уведомление, дальше фабрика не идёт. Обычно это «Ручная»: владелец проверяет и отмечает её той же командой;
   2. если статус задачи не Review, `backlog task edit SH-NNN -s Review`. Затем, если файл задачи изменён и не закоммичен (статус, отметки владельца), `git add <файл задачи>` и коммит `chore(backlog): SH-NNN на ревью`. Условие коммита — изменённый файл, а не значение статуса: так повтор после сбоя `git commit` не оставит статус незакоммиченным;
   3. `git push -u origin sh-NNN-…`;
   4. если `pr_url` есть, фабрика больше ничего не вызывает: пуш обновил PR. Если `pr_url` пуст, она ищет открытый PR ветки (`gh pr list --head <ветка> --state open --json url`); нашла — пишет ссылку в `pr_url`. Не нашла — `gh label create factory --force`, затем `gh pr create --title "SH-NNN: <название>" --label factory --body-file <git common dir>/factory/SH-NNN/pr-body.md`, последнюю непустую строку вывода (ссылку `https://…`) пишет в `pr_url`;
   5. этап «PR», уведомление.
4. Комментарий перед `## Задача` удаляется. Раздел «Чек-лист ревью» остаётся как в шаблоне, без отметок: его проверяет владелец. Первая строка тела — «Собрано фабрикой». Разделы:
   - «Задача»: `SH-NNN: <название>, файл задачи в backlog/tasks/`;

   - «Как проверено» — строки по порядку:
     - `- pnpm verify: <verify_summary>`;
     - `- Проверка тестов: <текст после двоеточия из последней строки заметок, которая начинается с «Проверка тестов:»>`; если такой строки нет или после двоеточия пусто — `- Проверка тестов: нет критериев с автоматическим уровнем`;

## Зачем
После проверок сессия задачи на Opus сейчас ставит Review, пушит ветку и открывает PR с описанием по шаблону. Всё это детерминированные шаги: данные для описания уже есть в задаче, заметках, состоянии и диффе. Фабрика делает их без модели и отдаёт владельцу PR, в котором видны итоги проверок, сомнительные места и критерии, которые нужно проверить ему.
