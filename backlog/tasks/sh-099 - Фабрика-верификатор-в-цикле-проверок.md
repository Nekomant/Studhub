## Что нужно сделать
1. Написать тесты по критериям до реализации в `tools/tests/factory.test.ts` с фикстурами SH-095. Подставной `claude` различает вызовы по аргументам (`--agent sh-worker`, `--agent sh-verifier`) и печатает заготовленный ответ для каждого.
2. Верификатор встаёт в цикл проверок SH-095 после чистого `pnpm verify`. Если в плане тестов нет критериев с уровнем Юнит, API или E2E, верификатор не запускается и строка итога не пишется. Иначе: `claude -p "Проверь SH-NNN" --agent sh-verifier --output-format json --permission-mode dontAsk --allowedTools <список верификатора> --max-budget-usd <лимит>`, `cwd` — worktree, окружение — как у `pnpm verify` в SH-095 (`scripts/lib/local-env.mjs`): верификатор запускает тесты с БД. Ответ сохраняется в папке задачи файлом `NNN-verifier.json`. Лимит — константа в `scripts/lib/factory-tools.mjs`, значение исполнитель записывает в заметки. Стоимость запуска прибавляется к `cost_usd`.
3. Разбор отчёта верификатора без модели:
   - строка `ПРОВЕРКА SH-NNN` обязательна;
   - строки разбора — только строки, которые начинаются с `AC-n:`; вердикт — первые слова сразу после `AC-n:` без учёта регистра и обрамления `*`: «подтверждён», «сомнительно» или «не подтверждён». Слова в пояснении после `—` не учитываются;
   - «не подтверждён» проверяется раньше «подтверждён»: второе слово входит в первое;
   - замечание: хотя бы один «не подтверждён» или строка «Нарушения правила…» после снятия кавычек и точки не равна «нет». Замечание уходит воркеру с источником `sh-verifier` и полным текстом отчёта по правилам кругов SH-095;
   - фраза для «сомнительно» — текст строки после первого «—»;
   - «сомнительно» не замечание: фабрика пишет такие строки в журнал, а в заметки они попадают с итогом (шаг 5). Владелец увидит их в PR (SH-101);
   - критерий автоматический, если хотя бы одна его строка в плане тестов требует метку (`levelNeedsLabel`); множество номеров в строках `AC-n:` должно совпадать с множеством автоматических критериев, а число строк — с их числом в плане тестов задачи (`parseTestPlan`, `levelNeedsLabel` из `scripts/lib/backlog-task.mjs`), а строка «Не смог проверить» после снятия кавычек и точки — «нет». Строка `AC-n:` без одного из трёх вердиктов, повтор номера или нет строки «Нарушения правила…» или «Не смог проверить» — тоже «ошибка проверок». «Ошибка проверок» важнее замечания: при обоих замечание воркеру не уходит.
4. Ошибки запуска: ненулевой код, невалидный JSON, `is_error: true` или `subtype`, начинающийся с `error` (так `claude` сообщает о превышении бюджета), нет строки `ПРОВЕРКА SH-NNN` — этап «ошибка проверок» с причиной в `reason`.
5. Чистый отчёт: фабрика пишет одну строку итога в заметки — `--append-notes "Проверка тестов: AC-1 подтверждён; AC-2 сомнительно: <фраза>; …"` — и сразу коммитит файл задачи (`git add <файл задачи>`, `chore(backlog): SH-NNN итог проверок`), чтобы worktree остался чистым. Задача без критериев с автоматическим уровнем строки не получает. Дальше цикл идёт, как в SH-095.
6. Список инструментов верификатора в `scripts/lib/factory-tools.mjs`: ровно `Read`, `Grep`, `Glob` и `Bash` именами инструментов, без правил `Bash(…)`. Bash верификатора ограничивает его хук `verifier-bash-guard.mjs` (команды чтения и запуск тестов), поэтому он может вызвать всё из своего описания: `node scripts/task.mjs`, `git diff`, `git log`, `git show`, `git branch`, `grep`, `cat`, `head`, `tail`, `wc`, `find`, `pnpm test`, `pnpm exec vitest run`.
7. Обновить документы (команды с флагами только в `README.md`):
    - `docs/process.md`, подраздел «Проверка тестов: sh-verifier»: в фабрике верификатор запускает фабрика; «сомнительно» не уходит воркеру, а попадает в заметки и в PR для владельца;
    - `CLAUDE.md`: строку о том, что сессия задачи вызывает `sh-verifier`, дополнить фабрикой.

## Зачем
Верификатор проверяет, что тесты действительно подтверждают критерии и их не подогнали под код. Сейчас его вызывает и разбирает сессия на Opus. Фабрика вызывает его в цикле проверок и разбирает отчёт по строкам, без модели-посредника.

## Контекст
- Процесс: `docs/process.md` §7.1, подраздел «Проверка тестов: sh-verifier».
- Агент: `.claude/agents/sh-verifier.md` (формат `ПРОВЕРКА SH-NNN`, команды в «Порядке проверки»), хук `scripts/hooks/verifier-bash-guard.mjs`.
- Фабрика: SH-095 (цикл проверок, круги, «ошибка проверок»), SH-098 (`matchesRule`, флаги).
- UC и экраны: нет, задача про процесс разработки.

## Не входит
- Ревью: SH-100.
- Изменение агента `sh-verifier`.

## Контракт
API и БД не меняются. Новое: вызов и разбор верификатора в `scripts/factory.mjs`, список инструментов и лимит верификатора в `scripts/lib/factory-tools.mjs`.
