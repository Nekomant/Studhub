## Что нужно сделать
1. Изучить итог прототипа OAuth (SH-013) и выбранный механизм входа для PWA на iOS.
2. Сделать заглушку сервера Яндекс ID для API-тестов и написать тесты по критериям до реализации.
3. Реализовать общий механизм `platform/oauth`: `start` (state и PKCE verifier в подписанной короткоживущей cookie, редирект), `callback` (проверка state, обмен кода, профиль), интерфейс провайдера.
4. Реализовать провайдера Яндекс ID.
5. Реализовать логику входа: поиск `auth_identity`, автосвязка по подтверждённому email, создание `user`, сессия, редирект на `/consent` или в приложение, ошибки через `/login?error=…`.
6. Добавить ограничение частоты на `start` и `callback`, событие `login` и тестового провайдера `test` для E2E (только `APP_MODE=test`).
7. Проверить логи на отсутствие токенов, кодов и email.

## Зачем
Регистрация и вход — одно действие через внешнего провайдера (ADR-0006). Яндекс ID — первый провайдер, на нём строится общий механизм OAuth.

## Контекст
- Сценарии: UC-01 (шаги 3–6, 10; 4а, 5а, 5б, 6а, 6б), UC-02 (2а).
- Экраны: Э-01 (сообщения `?error=`), `screens.md` §3.3.
- Правила: ТД §4.2 (инварианты автосвязки), §9 (`state` + PKCE, строгие адреса возврата, ограничение частоты), ADR-0006.
- Итог прототипа «OAuth в установленной PWA» (заметки задачи и ADR-0006).

## Не входит
- VK ID — задача «Вход через VK ID».
- Согласия и кабинет — задача «Согласия и создание кабинета» (до согласий пользователь перенаправляется на `/consent`).
- Привязка второго способа — задача «Привязка второго способа входа».
- Экран входа — задача «Экраны входа и согласий».

## Контракт
- `GET /api/v1/auth/yandex/start` → 302 к провайдеру.
- `GET /api/v1/auth/yandex/callback?code&state` → 302 на `/consent` (есть непринятые документы) | исходный адрес или `/` | `/login?error=cancelled|failed|provider_unavailable`.
- 429 `rate_limited`.

## План тестов
| AC | Уровень | Тест |
|---|---|---|
| 1 | API | редирект содержит state, `code_challenge_method=S256`, redirect_uri из конфига |

| 3 | API | повторный вход → тот же user |

| 7 | API | событие login; проверка логов на отсутствие токенов и email |
| 8 | API | превышение лимита → 429 |

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `GET /auth/yandex/start` перенаправляет к Яндекс ID с `state` и PKCE (`S256`); адрес возврата берётся только из конфигурации
- [ ] #2 Callback с новым аккаунтом провайдера создаёт `user` и `auth_identity`, создаёт сессию и перенаправляет на `/consent` (UC-01, шаг 6)
- [ ] #3 Повторный вход тем же аккаунтом провайдера не создаёт пользователя, создаёт сессию и перенаправляет в приложение (UC-01, 6а)
- [ ] #4 Если провайдер вернул подтверждённый email, совпадающий с email существующего пользователя, новый `auth_identity` привязывается к нему; при неподтверждённом email создаётся новый пользователь (UC-01, 6б)
- [ ] #5 Неверный или просроченный `state`, несовпадение PKCE или ошибка обмена кода → `/login?error=failed`, сессия не создаётся (UC-01, 5а)
- [ ] #6 Отказ пользователя у провайдера → `/login?error=cancelled` (4а); недоступность провайдера (таймаут, 5xx) → `/login?error=provider_unavailable` (5б)
- [ ] #7 Успешный вход пишет событие `login` в `product_event` без ПДн; в логах нет токенов, кодов авторизации и email
- [ ] #8 Частота запросов к `start` и `callback` ограничена: при превышении — 429 `code: rate_limited`
