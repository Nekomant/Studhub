Definition of Done, план, заметки, комментарии и итог в вывод не входят: там могут быть рассуждения штаба. Формат сделать чистой функцией рядом с `formatCriteria`, чтобы тестировать без `backlog`.

Без флага хук работает как сейчас. Текст блокировки называет агента по режиму.
4. Создать субагента `.claude/agents/sh-spec-critic.md` по образцу `sh-verifier`: инструменты Read, Bash, Grep, Glob, модель `sonnet`, `effort` и `maxTurns` как у `sh-verifier`; хук PreToolUse на Bash запускает `verifier-bash-guard.mjs --mode spec-critic`. Вход: только ID задачи, промпт «Проверь спецификацию SH-NNN». Один вызов проверяет одну задачу.

   - прочитать тем же режимом задачи из зависимостей и задачи, на которые ссылаются «Контекст» и «Не входит»: проверить, что работа не дублируется и ничего не выпало между задачами;
   - прочитать разделы из «Контекста» через `node scripts/doc.mjs`; затем найти `grep` по `docs/` ключевые слова задачи (таблицы, эндпоинты, cookie, экраны, UC) и прочитать найденные разделы, даже если «Контекст» их не называет. ТД, `use-cases.md` и `screens.md` целиком не читать;
   - найти непроверяемые критерии: нет наблюдаемого результата; субъективная формулировка («удобно», «быстро» без числа); одно утверждение смешивает несколько проверок; уровень в «Плане тестов» не подходит критерию (поведение API на уровне «Ревью», путь через экраны на уровне «Юнит»);
   - найти противоречия задачи с `product-concept.md`, `use-cases.md`, `screens.md`, ТД и ADR: назвать документ и раздел и указать, какой документ главнее по списку из `CLAUDE.md`. Если задача сама меняет этот документ (есть шаг в «Что нужно сделать» и критерий про правку документа), это не противоречие, а изменение решения: записать как «замечание», чтобы владелец увидел его в PR;

   КРИТИКА SH-NNN

   Непроверяемые критерии: AC-n: <почему> → <как переписать> | нет
   Противоречия: <шаг или AC-n> ↔ <документ §>: <суть>; главнее: <документ> | нет

   - с замечанием, которое штаб не принимает, он не спорит молча: в описании PR спецификаций пишет вердикт критика по каждой задаче и непринятые замечания с причиной;

## Зачем
Скрипт SH-089 проверяет форму спецификации, но не смысл. Критерий «интерфейс удобный» проходит все его проверки, а тест на него написать нельзя, и это вскрывается только когда рабочая сессия берётся за задачу. Расхождение с ТД, use-cases и screens тоже находит позже сам исполнитель, и его работа останавливается блоком `СТОП`. Независимый критик, который не видит рассуждений штаба, находит такие места до PR, пока правка стоит одной строки, а владелец видит в PR, что осталось спорным.
