## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Что нужно сделать
1. Подключить pg-boss в `platform/jobs`: запуск вместе с HTTP в `main.ts`, отдельная схема в той же БД, корректная остановка.
2. Сделать API для модулей: объявить периодическую задачу (cron) и задачу по событию с политикой повторов.
3. Логировать ошибки задач без ПДн и убедиться, что падение задачи не влияет на обработку HTTP.
4. Дать тестам способ выполнить задачу синхронно, без ожидания расписания.
5. Добавить служебную задачу-пример (heartbeat раз в минуту) и написать тесты по критериям.

## Зачем
Автоматические статусы уроков, генерация расписания, очистка и удаление аккаунтов работают как фоновые задачи (ТД §12). Механизм нужен до этапа 3, а риски интеграции лучше снять в каркасе.

## Контекст

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. platform/jobs: createJobs({databaseUrl, logger}) поверх pg-boss (схема pgboss, та же БД): define, start, stop, send, runNow, stats, isRunning.
2. Объявление задачи: имя, cron (необязательно), политика повторов, обработчик. Очередь создаётся при start, политика из кода обновляется при каждом старте.
3. Ошибка задачи: счётчик и лог error с job, jobId, attempt, willRetry, errorName, errorCode. Текст ошибки и данные задачи в лог не идут.
4. main.ts: jobs.start() после serve, ошибка запуска логируется, HTTP живёт; SIGTERM/SIGINT останавливают HTTP и jobs.
5. platform/heartbeat: задача-пример * * * * *.
6. Тестовый режим: /__test/jobs (состояние), /__test/jobs/:name/run (синхронно), /__test/jobs/:name/send (в очередь), тестовая задача test.flaky.
7. Тесты: юнит (apps/api, логи без ПДн, runNow, define) и API (tests/api: схема pgboss, schedule, событие, повторы при живом HTTP, синхронный запуск).
8. Правка ТД §12, §14 (тестовые маршруты) и process §8.3.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Оценка: 4 ч

Решение: pg-boss стартует после serve, ошибка запуска логируется, HTTP продолжает отвечать (как при недоступной БД, /healthz 503).

Решение: в лог идут errorType и errorCode, текст ошибки и данные задачи не логируются. Поле названо errorType, потому что маскировка pino скрывает ключи со словом name. Критерии не менялись.

Решение: красный API-коммит упал на отсутствии /__test/jobs, юнит-коммит на отсутствии модуля jobs.

Решение: cron-срабатывание по времени в тестах не ждём. Проверяем строку в pgboss.schedule с cron '* * * * *'. Выполнение по событию проверяем по состоянию строки в pgboss.job.

Решение: при SIGTERM процесс закрывает HTTP, ждёт активные задачи до 5 с и выходит (harness убивает через 5 с).

Факт: 2 ч

Проверка sh-verifier: все 4 критерия подтверждены автоматическими тестами, тесты после красного коммита не ослаблены (только переименование errorName в errorType), нарушений процесса нет. Замечание без снижения вердикта: отсутствие ПДн в логе проверено юнит-тестом через runNow, а не на логе реального процесса.

Ревью: исправлены замечания 1-6 (повтор запуска, снятие старых расписаний, остановка с ожиданием HTTP и кодом выхода, закрытие экземпляра при ошибке start, 400 на битый JSON в тестовых маршрутах, очередь создаётся с политикой повторов).
