## Что нужно сделать
1. Владелец: создать приватный репозиторий на GitHub; подключить его как `origin`.
2. Создать workflow GitHub Actions на PR и push в `main`: установка с кэшем pnpm, Biome, tsc, Vitest, API-тесты с сервисом `postgres:18`, `db:check`, проверка актуальности клиента, Playwright с кэшем браузеров, сборка образа без публикации.
3. Написать `scripts/check-ac-coverage`: берёт задачи в статусах Review и Done из Backlog.md (`backlog task list --json` или файлы `backlog/tasks`), ищет метки `[SH-NNN AC-n]` в тестах и печатает непокрытые критерии; покрыть юнит-тестом на фикстурах и подключить в CI.
4. Создать `.github/pull_request_template.md` по `docs/process.md` §9–10.
5. На тестовом PR убедиться, что каждый вид сломанной проверки делает CI красным; записать время прогона.
6. Владелец: включить защиту `main` (слияние только через PR при зелёном CI).

## Зачем
Процесс «спецификация → тесты → код» держится на автоматических проверках: PR с красными проверками или непокрытыми критериями не сливается.

## Контекст
- ТД §12 «CI».
- `docs/process.md` §6 (DoD), §8.2 (метки `[SH-NNN AC-n]`), §9 (PR).

## Не входит
Публикация образа и деплой — задача «Docker-образ и деплой».

## Контракт
Нет.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 На каждый PR и push в `main` выполняются все проверки ТД §12 «CI»; упавший шаг делает проверку красной
- [ ] #2 `scripts/check-ac-coverage` для каждой задачи в статусе Review или Done проверяет, что каждый критерий приёмки упомянут меткой `[SH-NNN AC-n]` хотя бы в одном тесте, и падает со списком непокрытых; скрипт входит в CI
- [ ] #3 Шаблон PR содержит: ссылку на задачу, что сделано, как проверено, изменения документов, чек-лист ревью из `docs/process.md` §10
- [ ] #4 Прогон CI на текущем проекте занимает не больше 10 минут благодаря кэшу
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 Каждый критерий приёмки покрыт тестом, в названии теста есть ID критерия (AC-n), все тесты зелёные
- [ ] #2 CI зелёный: Biome, tsc, Vitest, API-тесты, E2E, миграции и OpenAPI-клиент актуальны (с момента, когда эти проверки появились в CI)
- [ ] #3 Документы (use-cases, screens, technical-design, ADR) обновлены в этом же PR, если поведение или решения изменились
- [ ] #4 Новые эндпоинты покрыты тестом изоляции (чужой кабинет → 404); в логах и product_event нет ПДн; деньги только в minor units
- [ ] #5 Пройдено ревью (/code-review и просмотр диффа владельцем), замечания закрыты
- [ ] #6 PR слит в main через squash, изменения выложены в prod (после появления деплоя)
- [ ] #7 В заметках задачи записаны оценка и фактическое время, решения по ходу работы и итоговое резюме
- [ ] #8 Владелец создал приватный репозиторий на GitHub и включил защиту `main`: слияние только через PR при зелёном CI
<!-- DOD:END -->
