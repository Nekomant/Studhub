## Что нужно сделать
1. Написать тесты по критериям до реализации: `tools/tests/factory.test.ts` (новый блок для `pnpm factory list`) и `tools/tests/ready-skill.test.ts` (файлы скилла, настройки, документы). Фикстуры для `list` те же, что у `pnpm factory run` (SH-093, SH-098): bare-репозиторий вместо GitHub, основная папка, файлы задач в `backlog/tasks`, ID из диапазона SH-9xx.
2. В `scripts/factory.mjs` вынести отбор кандидатов из `main` в функцию, которую вызывают `run` и `list`. Поведение `run` не меняется: тесты SH-093 и SH-098 остаются зелёными без правок.
3. Добавить подкоманду `list`. Она делает `git fetch origin` (как `run`), читает задачи из `origin/main` и печатает без вопросов. Формат самостоятельный, не копия вывода `run`: по строке на кандидата `SH-NNN<TAB>приоритет<TAB>название`, по возрастанию номера, приоритет «не указан», если его нет; затем, если есть задачи, ждущие зависимость, блок `Ждут зависимость:` с такими же строками без причины ожидания. Кандидатов нет: первой строкой `Задач в Ready нет`, блок ожидающих после неё, если он есть. Код выхода 0. `list` ничего не создаёт и не запускает. Сбой `fetch` даёт тот же вывод и код, что у `run`. Сообщение об использовании в `main` становится `pnpm factory run [SH-NNN] [--foreground] | list`; у `list` нет аргументов и флагов, лишнее даёт код 2.
4. Создать скилл `.claude/skills/ready/SKILL.md`. Во frontmatter `name: ready`, `description` (как у `sh-task` и `sh-spec`) и `disable-model-invocation: true`: скилл вызывает только владелец командой. Без `hooks` и без `model`. Команда `/ready SH-NNN` или `/ready` без номера. Это единственное имя: каталога `.claude/commands` нет, а `pnpm factory run` упомянут в `.claude/skills` только в `ready/SKILL.md`. `.claude/settings.json` скилл не трогает: разрешений ему заранее не выдаётся, обычные запросы приложения остаются. Порядок скилла:
   1. Номер принимается только в виде `SH-NNN` (регистр не важен, как у `run`); другой ввод скилл не угадывает, а спрашивает владельца.
   2. Номер указан: запустить `pnpm factory run SH-NNN`. Номер не указан: запустить `pnpm factory list`. Нет кандидатов: ответить «Задач в Ready нет» (и показать блок ожидающих, если он есть) и остановиться. Один кандидат: запустить `pnpm factory run SH-NNN` для него. Несколько: показать список владельцу, спросить номер, потом запустить `pnpm factory run SH-NNN` для выбранного. Скилл никогда не вызывает `pnpm factory run` без номера (команда спросит ввод и зависнет) и никогда не использует `--foreground` (воркер занял бы сессию на часы).
   3. `pnpm factory run` готовит ветку и worktree и ставит зависимости, поэтому его запускают с таймаутом 10 минут. После подготовки воркер идёт фоновым процессом, а команда сразу завершается.
   4. Успех: код 0 и в выводе строка `SH-NNN: воркер запущен`. Ответить владельцу одной строкой: ID, ветка, путь к журналу (строки `Ветка:` и `Журнал:` из вывода).
   5. Код `list` или `run` не 0 (в том числе лимит двух живых процессов, задача не кандидат), либо в выводе нет строки «воркер запущен»: показать вывод владельцу и остановиться.
   Цикла по списку кандидатов в скилле нет: за одну команду запускается одна задача. Сессию в приложении скилл не открывает: воркер идёт фоновым процессом `claude -p --agent sh-worker` на Sonnet, как задаёт SH-098. Остановки, вопросы воркера и ответы на них не входят: это SH-094.
5. Обновить документы:
   - `README.md`, раздел фабрики: описать `pnpm factory list` и скилл `/ready`, коды выхода `list`.
   - `tools/tests/docs-dedup.test.ts`: добавить `pnpm factory list`. README описывает его без флагов; флаги `run` (`--foreground`) к `list` не относятся, поэтому для `list` тест проверяет только упоминание команды в README.
   - `docs/process.md` §7 (абзац «Основной способ») и §7.1 (абзац «Основной способ старта»): в обоих местах дословно предложение из критерия 20. Строки с `pnpm factory run` остаются в абзацах со ссылкой на README (правило SH-081).
   - `docs/process.md` §7, абзац «Старт выполнения задачи ручной», п. 4 `docs/adr/0010-factory.md` и строка про фабрику в `CLAUDE.md`: добавить дословно «/ready — прямая команда владельца» (без обратных кавычек).
   - `docs/adr/0010-factory.md`: добавить решение 5 «Команда старта в приложении: `/ready`» и абзац, который начинается словами «Пункт 2 дополняется:». В нём: модель сессии, где набрана `/ready`, читает вывод скрипта и запускает одну команду (два-четыре запроса, около 77 тыс. токенов контекста на запрос у обычной сессии). От отклонённой управляющей сессии это отличается тем, что владелец сам набирает команду и сессия не ведёт цикл задачи; воркер остаётся фоновым процессом на Sonnet по агенту `sh-worker`, сессий в приложении не добавляется.
6. Владелец: после слияния PR проверить вручную. `/ready SH-NNN` на реальной задаче в Ready (критерий 13). Варианты «кандидатов нет», «один» и «несколько» (критерии 14–16) проверить во временном клоне, где в `origin/main` нужное число задач в Ready. Результат записать в заметки задачи.

## Зачем
Запуск задачи сейчас требует выйти в терминал и набрать `pnpm factory run`, выбрав номер. Нужна одна команда в приложении, которую владелец набирает сам, поэтому правило ручного старта не нарушается. Короткое имя `/ready` одно, номер задачи необязателен. Подход «открыть в приложении сессию с `sh-worker`» отклонён 2026-11-14: после SH-098 фабрика сама ведёт воркера фоном, вторая сессия запускала бы его дважды.
