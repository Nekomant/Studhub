## Что нужно сделать
1. Описать в Drizzle таблицы `user`, `auth_identity`, `session`, `consent`, `workspace`, `workspace_member`, `product_event` по ТД §4.1–4.2, §4.9 и сгенерировать миграцию.
2. До реализации написать API-тесты по критериям (продление сессии — через управляемые часы).
3. Реализовать в `platform/sessions` создание сессии (случайный токен, в БД — SHA-256), чтение из cookie `sh_session` и `Authorization: Bearer`, скользящее продление.
4. Сделать middleware аутентификации: 401 `unauthenticated` без валидной сессии; проверка `Origin` у изменяющих запросов с cookie.
5. Реализовать `GET /me`, `POST /auth/logout`, `POST /auth/logout-all`.
6. Добавить тестовый помощник создания пользователя и сессии (только `APP_MODE=test`).

## Зачем
Основа входа: кто пользователь и как он остаётся в системе 90 дней без повторного входа (UC-02).

## Контекст
- Сценарии: UC-02 (шаг 2, «Выход»).
- Правила: ТД §4.2 (таблицы и инварианты), §4.9 (`product_event`), §6.1 (аутентификация, Origin), ADR-0006.

## Не входит
- OAuth — задачи «Вход через Яндекс ID», «Вход через VK ID».
- Согласия и создание кабинета — задача «Согласия и создание кабинета».

## Контракт
- `GET /api/v1/me` → `{ id, displayName, avatarUrl, timezone, workspaces: [{ id, name, role }] }`.
- `POST /api/v1/auth/logout` → 204; `POST /api/v1/auth/logout-all` → 204.
- Ошибки: 401 `unauthenticated`, 403 `origin_mismatch`.

## План тестов
| AC | Уровень | Тест |

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Миграции создают таблицы `user`, `auth_identity`, `session`, `consent`, `workspace`, `workspace_member`, `product_event` с ограничениями из ТД §4.1–4.2 и §4.9
- [ ] #2 Запрос к защищённому эндпоинту без сессии, с неизвестным или истёкшим токеном → 401 `problem+json` с `code: unauthenticated`
- [ ] #3 Сессия принимается из cookie `sh_session` (`httpOnly`, `Secure`, `SameSite=Lax`, 90 дней) и из `Authorization: Bearer`; в таблице `session` хранится только SHA-256 токена
- [ ] #4 Если до истечения сессии осталось меньше 45 дней, запрос продлевает её на 90 дней от текущего момента и обновляет cookie; при большем остатке срок не меняется
- [ ] #5 Изменяющий запрос с cookie и отсутствующим или чужим `Origin` → 403 `code: origin_mismatch`; для Bearer проверка `Origin` не применяется
- [ ] #6 `GET /me` возвращает профиль текущего пользователя и список его кабинетов с ролью
- [ ] #7 `POST /auth/logout` удаляет текущую сессию и очищает cookie; `POST /auth/logout-all` удаляет все сессии пользователя; их токены после этого дают 401
<!-- AC:END -->
