## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Что нужно сделать
1. Написать API-тесты по критериям до реализации.
2. Реализовать `GET /auth/{provider}/link` поверх общего механизма OAuth для вошедшего пользователя.
3. Реализовать `GET /me/identities` и `DELETE /me/identities/{id}` с запретом отвязать последний способ.
4. Сверстать раздел «Способы входа» в Э-17 и точку-напоминание в Э-16.
5. Написать E2E-тест входа вторым провайдером в тот же кабинет.

## Зачем
Писем в MVP нет, поэтому второй провайдер — единственный способ не потерять доступ (ADR-0006).

## Контекст
- Сценарии: UC-03.
- Экраны: Э-17 «Способы входа», Э-16 (точка-напоминание), П-5.
- Правила: ТД §4.2 (отвязать можно любой способ, кроме последнего), ADR-0006.

## Контракт
- `GET /api/v1/auth/{provider}/link` → 302 … → `/more/settings/login?linked=…|error=identity_in_use`.
- `GET /api/v1/me/identities` → `[{ id, provider, email, createdAt }]`.
- `DELETE /api/v1/me/identities/{id}` → 204 | 409 `last_identity`.

## План тестов
| AC | Уровень | Тест |
|---|---|---|
| 1 | API + E2E | привязка через тестового провайдера |
| 2 | API | аккаунт другого пользователя → identity_in_use |
| 3 | API | список; отвязка; последний → 409 |
| 4 | E2E | подсказка и точка при одном способе |
| 5 | E2E | вход вторым провайдером в тот же кабинет |
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `GET /auth/{provider}/link` проводит вошедшего пользователя через OAuth и привязывает новый `auth_identity` к нему; пользователь возвращается в Э-17 «Способы входа» с результатом
- [ ] #2 Если аккаунт провайдера уже привязан к другому пользователю, привязка не выполняется и показывается «Этот аккаунт уже используется другим пользователем» (`identity_in_use`)
- [ ] #3 `GET /me/identities` возвращает провайдера, email и дату привязки; `DELETE /me/identities/{id}` отвязывает способ входа, если он не последний; для последнего — 409 `last_identity`
- [ ] #4 Если привязан один способ входа, в Э-17 показывается подсказка о втором, а пункт «Настройки» в Э-16 отмечен точкой-напоминанием
- [ ] #5 После привязки второго провайдера пользователь входит через любой из них в тот же кабинет
<!-- AC:END -->
