## Что нужно сделать
1. Написать тесты по критериям до реализации в `tools/tests/factory.test.ts` с фикстурами SH-095 и SH-099. Подставной `claude` различает вызов ревью по аргументу `/code-review`.
2. Ревью встаёт в цикл проверок SH-095 после чистого отчёта верификатора (SH-099), а если верификатор не запускался (нет автоматических критериев) — после чистого `pnpm verify`: `claude -p "/code-review high" --model sonnet --append-system-prompt "Последней строкой выведи: ЗАМЕЧАНИЙ: <число>" --output-format json --permission-mode dontAsk --allowedTools <список ревью> --disallowedTools <запреты ревью> --max-budget-usd <лимит>`, `cwd` — worktree. Лимит — константа в `scripts/lib/factory-tools.mjs`, значение исполнитель записывает в заметки. Стоимость запуска прибавляется к `cost_usd`.
3. Разбор ответа: из строк, равных `ЗАМЕЧАНИЙ: <целое ≥ 0>`, берётся последняя, даже если после неё есть другой текст. Число фабрика пишет в `review_count` после каждого разобранного ответа. Число больше 0 — замечание воркеру с источником `code-review` и полным текстом ревью по правилам кругов SH-095.
4. Ошибки запуска: ненулевой код, невалидный JSON, `is_error: true` или `subtype`, начинающийся с `error`, нет строки `ЗАМЕЧАНИЙ: <число>` — этап «ошибка проверок» с причиной в `reason`.
5. Чистое ревью (`review_count` 0): цикл идёт к этапу «готово к PR».
6. Список ревью в `scripts/lib/factory-tools.mjs`: Read, Grep, Glob, Agent и Bash для `git diff`, `log`, `show`, `status`, `branch --show-current`, `rev-parse`, `merge-base`, `cat`, `ls`, `head`, `tail`, `wc`; запреты: имена инструментов Edit и Write, правила `git commit`, `git push`, `git branch -D`, `git branch -d`, `gh`. Сопоставление команд — через `matchesRule` из SH-098, запрет сильнее разрешения. Запись в файл через `--output` у `git diff`, `git log` и `git show` правилом по префиксу не запретить: это принятый риск из ADR 0010, ревью не должно писать файлы по своему описанию.
7. Обновить документы:
    - `docs/process.md` §7.1 (шаг 5): в фабрике ревью идёт на Sonnet с уровнем `high`; Opus подключается, когда фабрика остановилась на «нужен штаб»;
    - `CLAUDE.md`: строку о том, что сессия задачи вызывает `/code-review`, дополнить фабрикой.

## Зачем
`/code-review` сейчас запускает сессия на Opus. По решению владельца в фабрике ревью идёт на Sonnet, а Opus подключается, только если фабрика остановилась. Фабрика запускает ревью в цикле проверок и читает число замечаний из последней строки ответа, без модели-посредника.

## Контекст
- Процесс: `docs/process.md` §7 (шаг 7), §7.1 (шаг 5), §10.
- Фабрика: SH-095 (цикл проверок, круги), SH-099 (верификатор перед ревью), SH-098 (`matchesRule`, флаги).
- Решение владельца: code-review в фабрике идёт на Sonnet, Opus подключается, только если фабрика остановилась.
- `/code-review` — встроенный скилл Claude Code, его нет в репозитории. Какие инструменты ему нужны в режиме `-p`, проверяет критерий 6.
- UC и экраны: нет, задача про процесс разработки.
