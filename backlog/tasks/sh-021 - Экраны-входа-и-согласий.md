## Что нужно сделать
1. В `client-core` сделать хранение сессии и текущего кабинета (nanostores) и обработку 401 и 403 `consent_required`.
2. Реализовать маршрутизацию по схеме `screens.md` §3.3 с возвратом на исходный адрес.
3. Сверстать Э-01: кнопки провайдеров, сообщения `?error=`, состояние без сети; в тестовом режиме — кнопка тестового провайдера.
4. Сверстать Э-02 в двух вариантах: первый вход и «Мы обновили документы».
5. Сделать «Сегодня» заглушкой с именем пользователя.
6. Написать E2E-тесты UC-01, UC-02 и остальных критериев.

## Зачем
Первое впечатление от продукта: вход в два нажатия и понятные согласия. Маршрутизация по схеме входа определяет, куда попадает пользователь.

## Контекст
- Сценарии: UC-01, UC-02 (E2E ✓ для обоих).
- Экраны: Э-01, Э-02, схема `screens.md` §3.3, Э-05 (заглушка), П-1, П-8.
- Правила: ТД §8 (слои клиента, глобальное состояние).

## Не входит
- Онбординг и настройки — задача «Настройки и онбординг: шаг 1».
- Плашки удаления аккаунта — этап 7.

## Контракт
Нет новых эндпоинтов.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Без сессии любой адрес приложения открывает Э-01; после входа пользователь возвращается на исходный адрес
- [ ] #2 Э-01 показывает сообщения для `?error=cancelled`, `failed`, `provider_unavailable` по `screens.md`; без сети кнопки входа неактивны с подсказкой
- [ ] #3 Новый пользователь после входа видит Э-02; «Начать» неактивна, пока не отмечены оба чекбокса; после согласия открывается следующий экран по схеме §3.3
- [ ] #4 При новой версии документа Э-02 показывается в варианте «Мы обновили документы» только с изменёнными документами, затем открывается «Сегодня»
- [ ] #5 «Выйти» на Э-02 завершает сессию и открывает Э-01
- [ ] #6 E2E-тесты UC-01 и UC-02 проходят через тестового OAuth-провайдера: регистрация → согласия → приложение; выход → вход → «Сегодня» без повторных согласий
<!-- AC:END -->
