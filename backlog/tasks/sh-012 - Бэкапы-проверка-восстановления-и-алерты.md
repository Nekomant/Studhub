## Что нужно сделать
1. Владелец: создать бакет у второго провайдера в РФ (например, Yandex Object Storage) и Telegram-бота для алертов.
2. Настроить wal-g для Postgres: архивация WAL, ежедневный полный бэкап, шифрование libsodium, хранение 30 дней.
3. Написать скрипт проверки восстановления: поднять копию во временном контейнере, сверить число строк ключевых таблиц; поставить в cron раз в неделю.
4. Написать cron-скрипт алертов в Telegram: бэкапу больше 26 ч, проверка восстановления упала, диск заполнен больше чем на 80%, мало памяти. Без ПДн.
5. Подключить UptimeRobot к `/healthz`.
6. Один раз выполнить восстановление на момент времени и описать шаги в `infra/README.md`.

## Зачем
Потеря данных преподавателя — главный риск доверия (ТД §16). Бэкап без проверки восстановления бэкапом не считается.

## Контекст
- Сценарий: UC-S5.
- ТД §12 «Бэкапы», «Наблюдение». ADR-0007.
