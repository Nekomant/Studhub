## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Что нужно сделать
1. Описать в Drizzle таблицу `admin_audit` по ТД §4.9 и ADR-0009, п. 5: `id`, `staff_user_id` (`NULL` значит система), `session_id`, `action`, `object_type`, `object_id`, `workspace_id` (без внешнего ключа), `result` (`ok` | `denied` | `error`), `ip`, `user_agent`, `details jsonb`, `at`. Сгенерировать миграцию.
2. Выдать приложению в БД на эту таблицу только право `INSERT` (отдельная роль БД или права в миграции). Решить и записать в заметки, как удалять записи старше года при таком праве: отдельная роль БД для очистки или партиции по месяцам.
3. Написать API-тесты по критериям до реализации.
4. Писать запись на каждый запрос к `/api/admin/v1`: и чтение, и команду, и отказ. Запись команды делать в той же транзакции, что и сама команда.
5. Добавить ежедневную задачу pg-boss, которая удаляет записи старше 1 года (ТД §12, раздел очистки). Если SH-007 ещё не в Done, задача зависит от него.
6. Описать в ТД §4.9 и §12 получившееся решение об удалении старых записей.

## Зачем
Админка читает все кабинеты, и главный вопрос при разборе инцидента «кто смотрел кабинет». Журнал, который приложение не может изменить или удалить, отвечает на него и сдерживает злоупотребления (ADR-0009, п. 5).

## Контекст
- Решение: ADR-0009, п. 5 и «Последствия» (как удалять старые записи решает эта задача).
- Правила: ТД §4.9 (`admin_audit`), §12 (фоновые задачи), §9 (ПДн в журнале запрещены).
- Зависит от SH-084 (middleware сотрудника) и SH-007 (pg-boss).

## Не входит
- Запись факта удаления аккаунта задачей UC-S4 с пустым `staff_user_id`: делает задача удаления аккаунта, использует эту таблицу.
- Экран просмотра журнала: отдельная задача стадии 3.
- Вход сотрудника и сессия: SH-085.

## Контракт
- Таблица `admin_audit` как выше; индексы по `at` и `staff_user_id`.
- Приложение: право только `INSERT` на `admin_audit`.
- Ежедневная задача очистки записей старше 1 года.

## План тестов
| AC | Уровень | Тест |
|---|---|---|
| 1 | API | миграция применяется; `result` вне списка отклоняется БД |
| 2 | API | `UPDATE` и `DELETE` из роли приложения отклоняются БД |
| 3 | API | чтение `GET /api/admin/v1/me` оставляет запись `ok` с `staff_user_id` и `session_id` |
| 4 | API | запрос без сессии, с неверной ролью или с ошибкой оставляет запись `denied` или `error` |
| 5 | API | запись команды в одной транзакции с командой: при откате команды записи нет, при откате записи нет и команды (тестовый эндпоинт `APP_MODE=test`) |
| 6 | API | `details` и `object_id` не содержат ПДн: тест на образцовом запросе |
| 7 | Юнит | задача очистки удаляет записи старше 1 года и оставляет свежие (управляемые часы) |
| 8 | Ревью | ТД §4.9 и §12 описывают способ удаления старых записей |
