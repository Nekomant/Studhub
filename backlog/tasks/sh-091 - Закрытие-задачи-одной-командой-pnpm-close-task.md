## Что нужно сделать
1. Написать `scripts/close-task.mjs` и команду `pnpm close-task SH-NNN [--apply]`. Скрипт запускают в основной папке клона. Без `--apply` он ничего не меняет и печатает вердикт; с `--apply` при положительном вердикте убирает за задачей.
2. Вердикт строится из трёх проверок, перед ними скрипт делает `git fetch --all --prune`:
   1. PR задачи слит. Скрипт ищет через `gh pr list --state all` PR с названием `SH-NNN: …` и читает `state` и `statusCheckRollup`.
   2. В `origin/main` у задачи статус Done: `git grep -n "^status:" origin/main -- "backlog/tasks/sh-NNN -*"` (пробел перед `-*` обязателен, иначе SH-08 совпадёт с SH-080). Файлы рабочей папки скрипт не читает: сессия задачи меняет статус в своём worktree, и в основной папке файл устаревший.
   3. Все проверки PR (`statusCheckRollup`) завершились `SUCCESS`; `SKIPPED` и `NEUTRAL` допустимы.
3. С `--apply` и положительным вердиктом скрипт:
   1. перематывает локальный `main` основной папки до `origin/main` (`--ff-only`, логика `pnpm sync --apply` повторно используется из `scripts/sync.mjs`);
   2. удаляет локальную ветку PR (`git branch -D`, после squash `-d` не сработает) и печатает её SHA, чтобы ветку можно было вернуть;
   3. удаляет worktree этой ветки или worktree на отсоединённой голове после перехода сессии на `origin/main`, только если он чистый; если в нём есть незакоммиченные файлы, оставляет его и называет в выводе.
4. Вывод компактный: до 12 строк, по строке на проверку и действие, последняя строка `ЗАКРЫТЬ СЕССИЮ: да` или `ЗАКРЫТЬ СЕССИЮ: нет (<причина>)`. Скрипт не архивирует сессию: это инструмент приложения, архивирует штаб по вердикту.
5. Добавить скрипт в `package.json` (`close-task`) и описать его в `README.md` рядом с `pnpm sync` и `pnpm status`.
6. Поменять порядок закрытия цикла в `docs/process.md` §7.1, шаг 7, и в `CLAUDE.md` (раздел «Штаб, спецификации и основная папка»). Было: владелец пишет сессии задачи, что PR слит, и она сама убирает за собой и архивирует себя. Стало: когда сессия задачи сообщает штабу, что воркер закончил и задача в Done, или владелец пишет штабу, что PR слит, штаб запускает `pnpm close-task SH-NNN --apply`, а при вердикте «да» архивирует сессию задачи (`archive_session`). Если PR ещё не слит, штаб ничего не удаляет и один раз пишет владельцу, чего не хватает. Сессия задачи после Done сама не удаляет ветку и не архивирует себя.
7. Написать тесты по критериям.

## Зачем
Закрытие цикла после слияния PR сейчас делается вручную: штаб или сессия задачи по очереди запускают `gh pr view`, `git fetch`, `git grep`, `pnpm sync --apply`, `git branch -D`, и каждый вызов попадает в контекст. Эти шаги детерминированные, их удобно выполнять одной командой, а в контексте оставлять одну строку вердикта. Кроме того, при ручной проверке легко прочитать статус из рабочей папки штаба: он там устаревший (так было с SH-073: в основной папке лежала копия со статусом Ready при Backlog в `origin/main`).

## Контекст
- Процесс: `docs/process.md` §7 (шаги 8–9), §7.1 (шаг 7), §9.
- Скрипты-образцы: `scripts/sync.mjs` (подтягивание `main`, `--apply`), `scripts/git-prune.mjs` (удаление веток с печатью SHA), `scripts/status.mjs` (вызов `gh`), `scripts/lib/git.mjs`.
- Решения владельца (2026-11-12): штаб после отчёта сессии о Done проверяет слияние и checks, обновляет `main`, удаляет рабочие ветки и закрывает сессию; рутину выносим в скрипт для экономии контекста.
- Особенность порядка: Done сессия задачи ставит последним коммитом ветки, и в `origin/main` он попадает только со слиянием PR. Поэтому отчёт о Done приходит до слияния, и штаб запускает скрипт повторно, когда владелец напишет, что PR слит.

## Не входит
- Архивация сессии: делает штаб инструментом приложения.
- Автоматический запуск скрипта по событию или по таймеру: запуск остаётся ручным действием штаба (решение «Ручной старт задач»).
- Слияние PR, запуск и остановка рабочих сессий.
- Правка `scripts/sync.mjs` сверх выноса переиспользуемой функции подтягивания `main`; поведение `pnpm sync` и его тесты не меняются.

## Контракт
