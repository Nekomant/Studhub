## Что нужно сделать
1. Сделать заглушку сервера VK ID и параметризовать API-тесты входа по провайдерам; добавить тест профиля без email.
2. Реализовать провайдера VK ID в общем механизме `platform/oauth` с учётом формата профиля и возможного отсутствия email.
3. Убедиться, что код провайдера Яндекс ID не менялся.

## Зачем
Второй провайдер страхует от потери доступа к аккаунту (ADR-0006) и даёт выбор тем, у кого нет Яндекс ID.

## Контекст
- Сценарии: UC-01, UC-02.
- Правила: ТД §4.2, §9, ADR-0006. Общий механизм — задача «Вход через Яндекс ID».

## Не входит
Привязка второго способа — отдельная задача.

## Контракт
- `GET /api/v1/auth/vk/start`, `GET /api/v1/auth/vk/callback` — как у Яндекс ID.

## План тестов
| AC | Уровень | Тест |
|---|---|---|
| 1 | API | тесты входа Яндекс ID, параметризованные провайдером `vk` |
| 2 | API | профиль без email |
| 3 | Ревью | дифф не меняет код провайдера Яндекс ID |
