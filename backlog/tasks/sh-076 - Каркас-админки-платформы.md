## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Что нужно сделать
1. Создать `apps/admin`: пакет `@studhub/admin` на Vite + React + TypeScript по образцу `apps/web` (SH-008), с `index.html`, точкой входа и одной страницей.
2. На странице показать заголовок «Админка платформы» и пометку «Заглушка: экраны появятся в следующих задачах». Страница не обращается к API, не просит вход и не показывает данных.
3. Подключить `apps/admin` к `pnpm check`, к сборке и к CI.
4. Добавить `apps/admin` в правила границ Biome (ТД §13): приложение не импортирует `apps/api`. Дополнить фикстуры и тест правил в `tools/`.
5. Написать E2E-тест заглушки в `tests/e2e`: страница открывается, показывает заголовок и пометку, не делает запросов к `/api` и к внешним доменам.
6. Описать в ТД §13 и в README, как запустить приложение (`pnpm --filter @studhub/admin dev`) и что оно пока пустое.

## Зачем
Остальные задачи админки (API сотрудников, вход, аудит, метрики) нужно куда-то подключать. Пустое приложение даёт им общий каркас, сборку и проверки границ, и не тянет за собой решения по входу и данным (ADR-0009).

## Контекст
- Решение: ADR-0009, п. 1 (отдельное приложение `apps/admin` на `admin.studhub.ru`).
- Правила: ТД §13 (структура репозитория, границы слоёв), §9 (без внешних CDN).
- Образец: SH-008 (`apps/web`).

## Не входит
- Вход, сессия, TOTP: SH-085.
- API `/api/admin/v1`, `platform_staff`: SH-084.
- Экраны, в том числе метрики Э-18: SH-088.
- Домен `admin.studhub.ru` и правила Caddy: SH-010 и деплой, отдельно.
- Общие компоненты с `apps/web`: заводим, только когда они понадобятся второму экрану.

## Контракт
Нет. API и БД не меняются.
