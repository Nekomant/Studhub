## Что нужно сделать
1. Изменить правило закрытия задачи в `docs/process.md` §3.1 и §7: статус Done ставит рабочая сессия последним коммитом в ветке задачи, и в `main` он попадает вместе со слиянием PR задачи. Отдельный PR на закрытие больше не нужен.
2. Порядок по умолчанию (владелец может поправить до Ready): сессия открывает PR со статусом Review. Владелец смотрит дифф и пишет сессии, что готов слить. Сессия коммитит Done, отмечает пункт DoD про слияние и пушит. Владелец сливает через squash.
3. Описать, что делать, если после коммита Done владелец просит правки: сессия возвращает статус Review, правит и снова ставит Done перед слиянием.
4. Обновить чеклист финиша в скилле `.claude/skills/sh-task/SKILL.md` и описание сессии задачи в `docs/process.md` §7.1.
5. Написать скрипт очистки локальных веток (`pnpm git:prune` или похожий): после `git fetch --prune` он находит ветки, у которых ветка на GitHub удалена (`[gone]`), пропускает ветки, открытые в любом worktree, и `main`. По умолчанию только печатает список, удаляет с флагом.
6. Описать скрипт в `docs/process.md` §9 и README.
7. Написать тесты по критериям.

## Зачем
Backlog.md хранит задачи файлами в репозитории, поэтому каждая смена статуса становится коммитом, а `main` защищён. Из 13 PR в репозитории 6 меняют только файлы в `backlog/`: это закрытия задач #2, #4, #6, #9, #11 и #13. Владелец выбрал оставить Backlog.md и ставить Done в PR задачи, а не переходить на GitHub Issues (решение 2026-11-12).

На GitHub уже включено автоудаление ветки после слияния и слияние только через squash. Локальные ветки после слияния остаются. Обычная проверка `git branch --merged` их не находит: после squash коммиты ветки не входят в историю `main`.

## Контекст
- `docs/process.md` §3.1 (статусы), §6 (DoD), §7 и §7.1 (жизненный цикл, агент `sh-worker`), §9 (Git).
- `.claude/skills/sh-task/SKILL.md`: чеклисты старта и финиша.
- `backlog/config.yml`: DoD по умолчанию, `check_active_branches: true` (доска видит статусы из активных веток).

## Не входит
- Переход на другой трекер.
- Ready без коммита: статус Ready по-прежнему переносит первым коммитом рабочая сессия.
- Пункт DoD про выкладку в prod: закрывается после SH-011, как сейчас.
- Автоархивация сессий: владелец её выключил, она действует на все проекты.

## Контракт
API и БД не меняются. Новая команда очистки веток в `package.json`.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Оценка: 3 ч

Решение: скрипт сам запускает git fetch --prune, затем берёт ветки с upstream [gone] из git for-each-ref (имя через refname:lstrip=2, чтобы тег с тем же именем не дал heads/…). Ветки из git worktree list --porcelain и main пропускает. Удаляет git branch -D: после squash ветка не считается слитой, и -d отказал бы.
Решение: тесты AC-3, AC-4 (tools/tests/git-prune.test.ts) собирают bare-репозиторий как GitHub и клон, запускают скрипт процессом. Проверка на рабочем клоне: pnpm git:prune без флага нашёл одну ветку claude/sh-003-local-env-760f8c, ничего не удалил.
Решение: CLAUDE.md (порядок работы и абзац про sh-worker) поправлен под новое правило, чтобы не расходился с process.md §7.
AC-1 и AC-5 проверены чтением диффа docs/process.md, скилла sh-task и README. AC-2 закрывает сессия задачи коммитом Done в этой ветке; после него отмечаются AC-2 и DoD #1, #2, #5, #6.
Факт: 1 ч

Ревью: скрипт печатает SHA каждой удалённой ветки (вернуть: git branch <имя> <SHA>), fetch идёт с --all; тест создаёт main явно для git до 2.31. В §7 и скилле при возврате в Review снимаются отметки DoD 2, 5, 6; номера DoD в скилле сверяются с task.mjs.
