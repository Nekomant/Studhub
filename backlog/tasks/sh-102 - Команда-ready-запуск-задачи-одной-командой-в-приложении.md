## Что нужно сделать
1. Написать тесты по критериям до реализации: `tools/tests/factory.test.ts` (новый блок для `pnpm factory list`) и `tools/tests/ready-skill.test.ts` (проверки файлов скилла, настроек и документов). Фикстуры для `list` те же, что у `pnpm factory run` (SH-093): bare-репозиторий вместо GitHub, основная папка, файлы задач в `backlog/tasks`, ID из диапазона SH-9xx.
2. В `scripts/factory.mjs` вынести отбор кандидатов из `main` в функцию, которую вызывают `run` и `list`. Поведение `run` не меняется: тесты SH-093 остаются зелёными без правок.
3. Добавить подкоманду `list`: она делает `git fetch origin` (как `run`; ошибка fetch даёт тот же вывод и код, что у `run`), читает задачи из `origin/main` и печатает без вопросов. Формат самостоятельный, не копия вывода `run`: по строке на кандидата `SH-NNN<TAB>приоритет<TAB>название`, строки по возрастанию номера, приоритет «не указан», если его нет, причина ожидания не печатается; затем, если есть задачи, ждущие зависимость, блок `Ждут зависимость:` с такими же строками. Кандидатов нет: первой строкой `Задач в Ready нет`, блок ожидающих после неё, если он есть. Код выхода 0. `list` ничего не создаёт. Сообщение об использовании в `main` становится `pnpm factory run [SH-NNN] | list`, лишние аргументы по-прежнему дают код 2.
4. Создать скилл `.claude/skills/ready/SKILL.md`. В frontmatter `name: ready`, `description` (как у `sh-task` и `sh-spec`) и `disable-model-invocation: true` (скилл вызывает только владелец командой), без `hooks`. Команда `/ready SH-NNN` или `/ready` без номера. Это единственное имя: каталога `.claude/commands` нет, а команда `pnpm factory run` упомянута в `.claude/skills` только в `ready/SKILL.md`. Порядок скилла:
   1. Номер указан: запустить `pnpm factory run SH-NNN`. Номер не указан: запустить `pnpm factory list`. Нет кандидатов: ответить «Задач в Ready нет» (и показать блок ожидающих, если он есть) и остановиться. Один кандидат: запустить `pnpm factory run SH-NNN` для него. Несколько: показать список владельцу, спросить номер, потом запустить `pnpm factory run SH-NNN` для выбранного. Скилл никогда не вызывает `pnpm factory run` без номера: он спрашивает ввод и зависнет.
   2. Код `pnpm factory list` или `pnpm factory run` не 0, либо `run` вернул 0 без строк `Ветка:` и `Worktree:`: показать вывод владельцу и остановиться, сессию не открывать.
   3. Взять из вывода `pnpm factory run` строки `Ветка:` и `Worktree:`.
   4. Открыть в приложении новую сессию в папке worktree без создания нового worktree (`start_session` с `cwd`, равным пути worktree, и `use_worktree: false`) на модели Sonnet (параметр `model` со значением `sonnet`, зафиксирован в скилле: решение владельца). Если вызвавшая сессия работает на более дешёвой модели, приложение оставляет её модель: это допустимо. Бриф сессии: вызвать `sh-worker` с промптом «Новый старт SH-NNN» (ID, ветка, «worktree уже на ветке, ветку не создавать») и вести цикл по `docs/process.md` §7.1. Процесс в брифе не пересказывать.
   5. Ответить владельцу одной строкой: ID и ссылка на сессию.
   Номер принимается только в виде `SH-NNN`; другой ввод скилл не угадывает, а спрашивает. `pnpm factory run` ставит зависимости, поэтому его запускают с длинным таймаутом (10 минут). Если сессию открыть не удалось, ветка и worktree уже есть: скилл показывает путь worktree и останавливается, повторный `run` откажет.
   Цикла по списку кандидатов в скилле нет: за одну команду запускается одна задача.
5. Обновить документы. Команды с флагами описать в `README.md` рядом с `pnpm factory run`: `pnpm factory list` и ссылка на скилл `/ready`; в `process.md` и `CLAUDE.md` упоминать `pnpm factory list` со ссылкой на README, без описания (правило SH-081). В README описать также коды выхода `list` (0; при сбое `fetch` как у `run`). `tools/tests/docs-dedup.test.ts`: добавить `pnpm factory list` в проверяемые команды. `docs/process.md` §7 (абзац «Основной способ») и §7.1 (абзац «Основной способ старта»): в обоих местах дословно предложение из критерия 19 (без обратных кавычек), других «основных способов» нет. Абзац §7 «Старт выполнения задачи ручной», п. 4 ADR-0010 и строка про основной способ в `CLAUDE.md`: добавить дословно «/ready — прямая команда владельца» (без обратных кавычек, как в критерии 20). `docs/adr/0010-factory.md`: добавить решение «Команда старта в приложении: `/ready`» и абзац, который начинается словами «Пункт 2 дополняется:». В нём: сам `/ready` модель использует только чтобы прочитать вывод скрипта и открыть сессию; открытая им сессия работает на модели и ведёт цикл по §7.1 (воркер, верификатор, review, PR, статусы), как при запасном способе. `CLAUDE.md`: блок про штаб.
6. Владелец: после слияния PR проверить вручную. `/ready SH-NNN` на реальной задаче в Ready (критерии 11 и 12). Варианты «кандидатов нет», «один» и «несколько» (критерии 13–15) проверить во временном клоне, где в `origin/main` нужное число задач в Ready. Результат записать в заметки задачи.

## Зачем
Запуск задачи сейчас занимает несколько шагов: команда `pnpm factory run` в терминале, затем просьба в чате открыть сессию в нужной папке. Нужна одна команда в приложении, которая делает всё сразу и которую владелец набирает сам, поэтому правило ручного старта не нарушается. Короткое имя `/ready` одно на всех: владелец не выбирает между вариантами.

## Контекст
- Процесс: `docs/process.md` §7 (шаг 3, ручной старт), §7.1 (шаги 1–4, запасной способ через штаб).
- Фабрика: ADR-0010, задача SH-093 (`pnpm factory run`), `scripts/factory.mjs`, `README.md` (раздел «Запуск задачи: `pnpm factory`»).
- Скиллы проекта: `.claude/skills/sh-spec/SKILL.md`, `.claude/skills/sh-task/SKILL.md` (образец формата).
- Решение владельца: команда называется `/ready`, номер задачи необязателен (обсуждение 2026-11-13); новая сессия открывается на модели Sonnet (2026-11-14).
- UC и экраны: нет, задача про процесс разработки.

## Не входит
- Запуск воркера фоновым процессом `claude` (SH-098). Эта задача его не меняет и не отменяет. Скилл `/ready` зависит от вывода `run`: строки `Ветка:` и `Worktree:`. Если SH-098 заменит их или запустит воркера сам, `/ready` начнёт запускать воркера дважды. SH-098 и эта задача правят один файл `scripts/factory.mjs`: их ведут по очереди, порядок решает владелец. Остальное решает владелец до старта SH-098: условие или флаг для записи, подготовленной `/ready`, добавит SH-098, а правка скилла будет в той задаче.
- Автозапуск: хуки, расписания, циклы по списку Ready. Скилл срабатывает только по команде владельца.
- Изменение отбора кандидатов и подготовки worktree: они остаются как в SH-093.
- Закрытие задачи после слияния (`pnpm close-task` и штаб).
