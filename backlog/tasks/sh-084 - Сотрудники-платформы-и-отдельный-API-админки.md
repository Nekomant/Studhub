## Что нужно сделать
1. Описать в Drizzle таблицу `platform_staff` по ТД §4.2 и ADR-0009, п. 4: `user_id`, `role` (`superadmin` | `support`), зашифрованный секрет TOTP, `created_at`, `disabled_at`. Сгенерировать миграцию.
2. Написать API-тесты по критериям до реализации.
3. Сделать отдельный модуль `admin` в `apps/api` и префикс `/api/admin/v1` со своей спецификацией OpenAPI и своим сгенерированным клиентом (ТД §6). Клиент для тестов генерируется так же, как клиент `/api/v1` (SH-006).
4. Сделать middleware сотрудника: по сессии находит запись `platform_staff`; нет сессии, нет записи или `disabled_at` не пусто → 404. Сама сессия появляется в SH-085, здесь middleware принимает сессию через тот же интерфейс.
5. Сделать функцию проверки роли для эндпоинтов: `support` не выполняет то, что разрешено только `superadmin` (403 с `code`). Покрыть её юнит-тестом: команд, доступных только `superadmin`, пока нет.
6. Реализовать `GET /api/admin/v1/me`: роль и `user_id` текущего сотрудника.
7. Добавить тестовый помощник создания сотрудника и его сессии (только `APP_MODE=test`).

## Зачем
Сотрудники платформы должны быть отдельной сущностью с ролями, не флагом у пользователя (ADR-0009, п. 4), а API админки отдельным от API преподавателя, чтобы сессии и права не смешивались. Это основа для входа, аудита и экранов админки.

## Контекст
- Решение: ADR-0009, п. 1 и 4.
- Правила: ТД §4.2 (`platform_staff`), §6 (админка платформы), §13.
- Сценарии: UC-P1 (актор «сотрудник платформы»).

## Не входит
- Вход через Яндекс ID или VK ID и TOTP, cookie `sh_admin_session`: SH-085.
- Журнал `admin_audit`: SH-086. До него middleware ничего не пишет в журнал.
- Маскировка ПДн учеников: SH-087.
- Команды поддержки (смена тарифа, блокировка): отдельные задачи стадии 3.
- Приложение `apps/admin`: SH-076.

## Контракт
- Таблица `platform_staff(user_id PK/FK user, role, totp_secret_encrypted, created_at, disabled_at)`.
- `GET /api/admin/v1/me` → `{ userId, role }`.
- Ошибки: 404 для всех, кто не сотрудник; 403 `forbidden_role` для недостаточной роли.
- Отдельная спецификация OpenAPI и клиент для `/api/admin/v1`.

## План тестов
| AC | Уровень | Тест |
