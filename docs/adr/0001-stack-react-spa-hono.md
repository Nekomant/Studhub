# ADR-0001: Стек — React SPA + Hono, граница через OpenAPI

- Статус: принято
- Дата: 2026-11-11

## Контекст

Кабинет закрыт логином, поэтому SEO и серверный рендеринг не нужны. Интерфейс мобильный и интерактивный: календарь, отметка урока в два касания, кэш PWA. Рано появятся другие клиенты: Telegram-бот (стадия 2), Mini App (3), мобильные приложения и школы (4). Разработчик один. Есть сквозное требование: сервер можно переписать на другом языке, фронтенд — на Vue.

## Решение

- Клиент: React SPA (Vite, TanStack Router, Query и Form). Логика клиента — в `packages/client-core` на TS без фреймворка.
- Сервер: Hono на Node 24, один сервис, который раздаёт и SPA, и `/api/v1`.
- Контракт — OpenAPI, генерируется из zod-схем (`@hono/zod-openapi`). Клиент генерируется по спецификации (`openapi-typescript` + `openapi-fetch`), а не через Hono RPC.
- Клиент и тесты API не импортируют код сервера.

## Рассмотренные варианты

- **Next.js:** серверные компоненты и правила кэша не окупаются без SSR, нет планировщика, логика оседает в Server Actions.
- **Nuxt 4:** рабочий вариант, но экосистема меньше, а неявных соглашений больше.
- **SvelteKit:** маленькая экосистема.
- **SPA + NestJS:** слишком много церемоний для такого объёма.
- **Laravel, Rails или Django:** два языка, нет общих типов.
- **BaaS:** доменную логику неудобно держать в БД, а облачные BaaS зарубежные.

## Последствия

- Клиент и сервер можно заменять независимо. Фронтенд переносится на Vue переписыванием только компонентов. Аналоги библиотек: shadcn-vue, vue-query, адаптер TanStack Form для Vue.
- При изменении API нужен шаг генерации клиента, CI проверяет его актуальность.
- Роутинг, слои и сборку настраиваем сами, без готового каркаса.
