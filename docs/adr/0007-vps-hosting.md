# ADR-0007: VPS + Docker Compose + wal-g вместо управляемых сервисов

- Статус: принято
- Дата: 2026-11-11

## Контекст

На стадии 1 продуктом пользуется один преподаватель-партнёр, на стадии 2 — 10–20. ПДн должны храниться в РФ. Важна цена и простота, но потеря данных об оплатах недопустима.

## Решение

- VPS в российском дата-центре (по умолчанию Selectel, 2 vCPU / 4 ГБ / 40 ГБ). На нём Docker Compose: Caddy (TLS, статика), app (Hono + pg-boss), PostgreSQL 18 без доступа снаружи.
- wal-g: непрерывная архивация WAL плюс ежедневный полный бэкап в S3 **другого** провайдера, с шифрованием, хранение 30 дней. Каждую неделю — автоматическая проверка восстановления, алерты по возрасту бэкапа.
- Файлы — в S3 провайдера VPS, с версионированием на 30 дней.
- Деплой: GitHub Actions → GHCR → SSH → `migrate` → `compose up`.

## Рассмотренные варианты

- **Yandex Cloud: ВМ + Managed PostgreSQL + Object Storage.** Надёжнее и без забот об эксплуатации базы, но в разы дороже на старте.
- **PaaS (Timeweb App Platform).** Проще деплой, но меньше контроля.

## Последствия

- Эксплуатация базы — на нас: обновления, мониторинг диска, проверка бэкапов.
- Отказоустойчивости нет. Простой на часы переживаем, потерю данных закрывают бэкапы.
- Переезд на Managed PostgreSQL при появлении платящих пользователей — это `pg_dump` / восстановление и смена строки подключения. Код не меняется.
