# ADR-0002: PostgreSQL 18 + Drizzle, pg-boss вместо Redis

- Статус: принято
- Дата: 2026-11-11

## Контекст

Смена СУБД маловероятна, а смена языка сервера возможна. Нужны удобство разработки, транзакции, сложные агрегаты (баланс, выписка, отчёты) и фоновые задачи.

## Решение

- PostgreSQL 18. В нём встроен `uuidv7()`, и это рекомендованная версия в Yandex Managed PostgreSQL на случай будущего переезда.
- Drizzle ORM + drizzle-kit. Схема описана в TS, миграции генерируются в SQL-файлы и проходят ревью. Свои SQL-миграции — для того, что генератор не умеет.
- Используем возможности Postgres вместо отдельных сервисов: очередь и cron через pg-boss, поиск через полнотекстовый поиск с русской морфологией и `pg_trgm`, `jsonb` для настроек, CHECK, частичные и составные уникальные ключи для инвариантов.

## Рассмотренные варианты

- **Kysely + dbmate:** максимальная переносимость, но миграции пишутся руками, а типы генерируются из живой БД.
- **Prisma:** собственный язык схем, нет CHECK, неудобный сложный SQL.
- **MikroORM, TypeORM:** тяжёлая модель или слабые типы.

## Последствия

- При смене языка сервера SQL-миграции один раз импортируются в новый инструмент: отмечаются в нём как уже применённые. Это несколько часов работы.
- Сгенерированные миграции обязательно читаем на ревью: генератор может спутать переименование с удалением.
- Redis не нужен. Вся инфраструктура данных — одна база, которую защищают бэкапы.
