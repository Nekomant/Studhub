# ADR-0005: Уроки хранятся строками на горизонт, слоты версионируются

- Статус: принято
- Дата: 2026-11-11

## Контекст

Регулярные слоты порождают уроки. Каждый урок редактируется независимо и почти каждый рано или поздно отмечается. Большинство экранов (календарь, «Следующий урок», неотмеченные, дашборд) — это запросы по урокам.

## Решение

- Уроки хранятся строками на горизонт «текущий месяц + следующий» в зоне слота. Ночная задача pg-boss продлевает горизонт, при изменении слота генерация идёт сразу.
- Уникальный ключ (`slot_id`, `occurrence_date`) делает генерацию идемпотентной.
- Слоты версионируются: изменение с даты X закрывает старую версию и открывает новую с тем же `series_id`. Будущие уроки старой версии перепривязываются к повторению новой в той же ISO-неделе. Запланированные получают новое время, остальные сохраняют своё. Нетронутые уроки без пары удаляются, тронутые становятся разовыми и попадают в сводку.

  **Обновлено 2026-11-11:** перенос меняет время того же урока и пишется в журнал `lesson_reschedule`; перенесённый вручную урок изменение слота не трогает. «Долг по уроку» — урок `postponed`. См. ТД §4.4, §4.5, §5.3 и [`screens.md`](../screens.md), Р-12.

## Рассмотренные варианты

- **Виртуальные повторения (RRULE + исключения, сохранение в БД при первом изменении):** бесконечный горизонт, но каждое чтение разворачивает правила с учётом зон, SQL-агрегаты невозможны, у клиентов API появляются виртуальные идентификаторы, а при переносе на другой язык переписывать пришлось бы ядро всех чтений.

## Последствия

- Все чтения — простой SQL. Сложность собрана в генераторе и изменении слота, оба покрыты тестами.
- За горизонтом календарь пуст, интерфейс показывает подсказку «Регулярные уроки построены до …».
- iCal-лента покрывает 1–2 месяца вперёд.
