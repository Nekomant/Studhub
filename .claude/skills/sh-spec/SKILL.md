# Спецификация задач: порядок и команды

Источник: `docs/process.md` §4 (шаблон), §5 (Definition of Ready), §7 шаги 1–2. Шаблон и Definition of Ready здесь не повторяются: читай их из документа.

1. Прочитай шаблон и Definition of Ready:
   - `node scripts/doc.mjs process 4`
   - `node scripts/doc.mjs process 5`
2. Работай в своём worktree, в ветке `specs-<тема>`. Основную папку не правь.
3. Прочитай разделы ТД, UC и экранов, на которые ссылается задача (`node scripts/doc.mjs td 4.1`, `uc UC-01`, `screens Э-01`). Документы целиком не читай.
4. Создай задачу. Описание передай в `-d`, критерии в `--ac` (по одному флагу на критерий), веху в `-m`, зависимости в `--dep`. План тестов пиши таблицей внутри описания.
   `backlog task create "Название" -d "…" --ac "…" --ac "…" -m m-0 --dep SH-010 -l infra --type task`
5. Проверь задачу, пока не исчезнут ошибки: `pnpm spec:check SH-NNN`. Скрипт проверяет структуру, зависимости и предупреждает о шагах владельца без «Владелец:». Смысл критериев ты проверяешь сам.
6. Переведи в Ready только задачи, которые предлагаешь взять в работу: `backlog task edit SH-NNN -s Ready`. Остальные оставь в Backlog.
7. Запусти `pnpm spec:check` без аргументов: он проверит все задачи в Ready.
8. Открой PR «Спецификации: SH-…». CI на PR сам запускает `node scripts/check-spec.mjs --changed`. Слияние PR владельцем означает согласование.

Подробности режимов скрипта: [README.md](../../../README.md).
