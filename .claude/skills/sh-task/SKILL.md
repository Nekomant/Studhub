# Задача SH-NNN: старт и финиш

Источник: `docs/process.md` §7 (жизненный цикл), §8 (тесты), §10 (ревью), §6 (DoD). При сомнении прочитай раздел: `node scripts/doc.mjs process 7`.

## Старт

1. `node scripts/task.mjs SH-NNN`: статус Ready, зависимости в Done, есть критерии и план тестов.
2. Ветка `sh-NNN-slug` в worktree от актуального `origin/main`, где задача уже в Ready: `git branch --show-current`. Файл задачи из основной папки не переноси, Ready не коммить.
3. `backlog task edit SH-NNN -s "In Progress" -a @claude`.
4. Прочитай разделы ТД, UC и экранов из «Контекста» задачи через `node scripts/doc.mjs`. Посмотри код, который задача меняет.
5. План: `backlog task edit SH-NNN --plan "1. …"`. Оценка первой строкой заметок: `--notes "Оценка: N ч"`.
6. План меняет решение из ТД или ADR? Остановись и верни вопрос.
7. Красные тесты по каждому критерию. Каждый тест начинается с `[SH-NNN AC-n]`. Тест падает по правильной причине (нет функции или эндпоинта), а не из-за ошибки в самом тесте. Уровень: правило — юнит, API и изоляция — API-тест, путь через экраны — E2E (§8.1). Отдельный коммит: `test(<модуль>): SH-NNN тесты по критериям приёмки`.

## Работа

- Реализация до зелёных тестов маленькими коммитами, потом рефакторинг.
- Тест под код без изменения критерия не меняй. Критерий кажется неверным? Остановись.
- Поведение или решение отличается от документов? Правь `docs/` в этой же ветке. Новое архитектурное решение оформи как ADR.
- Решения по ходу записывай: `backlog task edit SH-NNN --append-notes "Решение: …"`.

## Финиш

1. `pnpm verify` зелёный.
2. Ревью по `docs/process.md` §10:
   - [ ] каждый критерий подтверждён тестом или проверкой в браузере;
   - [ ] границы слоёв ТД §13: `domain/` чистый, клиент знает только OpenAPI;
   - [ ] бизнес-правила только на сервере;
   - [ ] доступ к данным через `ctx`, на каждый новый эндпоинт кабинета тест «чужой кабинет → 404»;
   - [ ] деньги в minor units, время в UTC, даты в зоне преподавателя;
   - [ ] в логах, событиях и ошибках нет ПДн;
   - [ ] ошибки API в `problem+json` с `code`;
   - [ ] нет кода вне задачи, закомментированного кода и TODO без задачи.
3. Критерии отмечай только с доказательством (зелёный тест, вывод команды): `backlog task edit SH-NNN --check-ac 1 --check-ac 2`.
4. Definition of Done отмечай по пунктам, которые уже выполнены: `--check-dod N`. Пункты «PR слит», «CI зелёный» и «ревью владельца» оставь сессии задачи.
5. Заметки: `--append-notes "Факт: N ч"` и решения по ходу.
6. Итог: `backlog task edit SH-NNN --final-summary "…"`: что сделано, как проверено, что изменилось в документах.
7. Верни отчёт `ГОТОВО SH-NNN` в формате из описания агента. Пуш, PR, `/code-review` и статус Review делает сессия задачи.

Review, Done и слияние ведёт сессия задачи (`docs/process.md` §7, шаг 9). Уборку после слияния (`pnpm close-task SH-NNN --apply`) и архивацию сессии делает штаб: §7.1, шаг 7.
